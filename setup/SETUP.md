# セットアップウィザード台本 — Claudeはこの手順で導入者と司令塔を作る

このファイルは**Claudeへの指示書**である。`hub.config.json` が未生成の状態で起動されたClaudeは、この台本に従って導入者にインタビューし、その人専用の司令塔一式を生成する。

**大原則：**
- 導入者は非エンジニアかもしれない。専門用語を避け、1度に1〜2問ずつ、対話で進める。
- **個人情報は導入者が話したことだけを書く。勝手に推測・創作して埋めない。**
- **情報の求め方は `setup/情報の預かり方.md` に従う。** インタビューの前に必ず読む。
- 各フェーズの終わりに「ここまでで作ったもの」を一言で報告する。
- **返事には導入者に向けた言葉だけを書く。** 「Q4へ。」「次はPhase 2」のような自分用の進行メモ、ファイル名やフェーズ番号だけの行を返事に混ぜない。
- 導入者は、ファイルを作るたびに「許可しますか？」の確認を何度も見ることになる。Phase 2 の生成に入る前に、「ここから確認が何度か出ます。作るのはこのフォルダの中だけです」と一言伝える。
- 途中で中断されても、次回起動時に生成済みファイルを確認してフェーズ途中から再開できるようにする。

---

## Phase 1：インタビュー（20〜30分）

最初に挨拶し、「あなた専用のAI司令塔を作る。いくつか聞いたら、あとはこちらで組み立てる」と全体像を伝える。

### はじめに：預かり方の説明（質問の前に必ず行う）

`setup/情報の預かり方.md` の「最初に説明する預かり方」の4点（送り先・置き場所・外に出る経路・渡さないもの）を、専門用語を避けて短く伝える。続けて、次の2つの趣旨を自分の言葉で伝える。

- **「私と情報を共有すればするほど、あなたに合った提案ができるようになります」**
- **「進めるのはゆっくりで大丈夫です。今日ぜんぶ揃える必要はなく、あとからいつでも足せます。渡したくないものは渡さなくて構いません」**

説明のあと、「ここまでで気になることはありますか」と一度だけ聞いてから質問に入る。

### 質問1：あなたのこと
- 名前と呼ばれ方
- 年齢（幅でもよい）
- 住んでいる地域（市区町村まで。番地は聞かない）
- 職場や学校、主な活動（仕事、学業、趣味、副業など）

各項目は、共有すると何が良くなるかを一言添えて聞く（`setup/情報の預かり方.md` の表）。答えたくない項目は飛ばし、空欄のまま進める。

### 質問2：人生の優先順位トップ3
- 「今のあなたにとって一番大事なことを3つ、順位付きで」
- これが司令塔の判断フィルターになることを説明する。

### 質問3：管理したい領域（＝部門）
- 「AIに手伝ってほしい生活・仕事の領域を挙げてください」と自由に話してもらう。
- 出てきた領域を**部門候補**として整理し、こちらから典型例も提示する：
  - タスク・予定管理 ／ お金・家計 ／ 健康・睡眠 ／ 学業・資格 ／ 仕事の案件管理 ／ 仕事探し・キャリア ／ 情報収集（AI・業界ニュース等） ／ 資産運用 ／ 生活コスト・暮らし ／ 趣味の記録（楽器・運動等） ／ 文書・メール作成
- **3〜6部門から始めることを推奨する**（後からいくらでも増やせる。`framework/05` パターン10）。最初から10部門以上は運用が回らなくなりがち、と正直に伝える。
- 各部門について「何を任せたいか」「今どこに記録があるか（Excel？メモアプリ？記録なし？）」を聞く。

### 質問4：判断のクセ・コミュニケーションの好み
- 大事にしている考え方（例：「お金で時間を買う」「慎重派」「まず試す派」）
- Claudeにどう接してほしいか（率直に指摘してほしい／丁寧に確認してほしい、口調など）

### 質問5：これまでの経験（履歴書）
- 「履歴書か職務経歴書があれば、それを渡してもらうのが一番楽です」と伝える。ファイルをこのフォルダに置いてもらうか、中身を貼ってもらう。
- 渡す前に、住所・電話番号・顔写真は消してよいと伝える。
- 履歴書が無ければ、学歴・職歴・これまでやってきたことを3〜5行で話してもらう。
- 「あとで」と言われたら、そのまま次へ進む。

### 質問6：普段使っているサービス
- 「普段使っているアプリやサービスを教えてください。名前と、何に使っているかだけで大丈夫です」と聞く。IDやパスワードは聞かない。
- 思い出しやすいよう、種類を挙げて聞く：予定・メモ／メール・連絡／家計・支払い／文書・表計算／ファイルの保存／仕事や学校で指定されているもの／AI。
- 全部を一度に挙げきらなくてよい。「思い出したら、いつでも足せます」と伝える。

### 質問7：外部連携の希望
以下を1つずつ「使いたいか」を聞く（全部「いいえ」でも司令塔は動く、と伝える）：
- **Obsidian**（スマホと同期するメモアプリ。タスクや走り書きの受信箱に使える）
- **Googleカレンダー**（予定の読み取り。設定に15分ほどかかる）
- **Notion**（既にNotionでデータ管理している人向け）
- **Claude in Chrome**（Claudeがブラウザ操作を代行）
- **ダッシュボード**（エージェントの活動をブラウザで眺められる画面）
- **日次報告**（毎朝、全部門が担当を確かめて、知らせることがある部門だけがダッシュボードに短く報告する。毎朝、部門の数だけClaudeが動くので、その分の使用量がかかると伝える。ダッシュボードとセットで使う。希望するなら走らせる時刻も聞く）
- **LINE通知**（日次報告を使う人だけ。毎朝の報告をスマホのLINEに1通で届ける。LINE公式アカウントを自分で作る準備が10分ほど要る。報告の中身がLINEを通ることも伝える）
- **会話ログからの学習**（日次報告を使う人だけ。毎朝、前日までの会話を読み返し、別々の会話で2回直されたことを覚えて次から守る。会話を読み返す分の使用量が増えると伝える。使い始めて1〜2週間たってから入れてもよい）

## Phase 2：生成（Claudeが自動で行う）

**生成の前に、OSとPythonコマンドを自己判定する**（導入者に聞く必要はない。Claude自身がこの環境で確認する）。

- **OS判定**：`platform.system()` 相当の情報（環境情報として渡されている場合はそれを使う。なければ `python3 -c "import platform;print(platform.system())"` を実行し、失敗したら `python -c "import platform;print(platform.system())"` を実行する）で `Darwin`（Mac）／`Windows`／`Linux` を判定する。
- **Pythonコマンド判定**：`python3 --version` を実行し、成功すれば `{{PYTHON_CMD}}` は `python3`。失敗したら `python --version` を実行し、成功すれば `python` を使う（**Windowsのネイティブ環境では `python3` コマンドが存在せず `python` のみのことが多い**。`||` 等のシェル連結記号には頼らず、2つのコマンドを別々に試すこと——PowerShellのバージョンによって対応する演算子が異なるため）。
- 判定結果は `hub.config.json` の `environment.os` / `environment.python_cmd` に記録し、以降のフック生成で一貫して使う。

インタビュー結果から以下を生成する。**生成前に部門構成の最終案を提示して一度だけ確認を取る**（「この構成で作ります。よいですか？」）。

1. **`shared/profile/ユーザープロファイル.md`** — `framework/templates/profile.template.md` を元に、聞いた内容で作成。聞けなかった欄は空欄のまま残す。
   - **`shared/profile/履歴書.txt`** — 質問5で預かった内容をそのまま置く（要約・言い換えをしない）。預かっていなければ作らない。
   - **`shared/profile/利用サービス一覧.md`** — `framework/templates/利用サービス一覧.template.md` を元に、質問6の内容で作成。
2. **`shared/共通プロトコル.md`** — `framework/templates/共通プロトコル.template.md` をコピーし、1のプロファイルの要約（200〜300字）を「1. ユーザープロファイル」の引用欄に書く。日次報告を使うなら `framework/templates/共通プロトコル_日次報告.template.md` も `shared/共通プロトコル_日次報告.md` としてコピーする。
3. **`my-hub/司令塔設定.md`** — `framework/templates/司令塔設定.template.md` を元に：
   - 人格調整（質問4の内容）
   - 部門表（番号・フォルダ名・担当領域・データソース・日次報告への参加・統合方式・既定ティア）
   - キーワード振り分け表（部門ごとに導入者が使いそうな言葉を5〜10個）
   - データ所有権表 ／ 部門間トリガー（あれば） ／ 外部連携の状態
4. **`agents/NN_名前/CLAUDE.md`** — 部門ごとに `framework/templates/agent.template.md` を元に作成。`examples/` の3例を書き方の参考にする。
   - 分割エージェントは最初は作らない（運用して必要になったら `framework/05` のパターンで増設）。
   - 日次報告を使うなら、各エージェントの「日次報告（Claude manager）」節に、その部門が読むだけで確かめる観点を2〜3個書く。参加させない部門は「参加しない」の1行にする。
5. **`shared/` のデータ置き場** — 部門ごとにフォルダを作る。既存の記録ファイル（Excel等）があれば置き場所を案内し、なければ空のファイル（見出し行だけのCSV等）を作って記録の型を提案する。
6. **`hub.config.json`** — `hub.config.example.json` を元に、実際のパス・連携のon/offを記入。`shared_info` には、預かった項目・「あとで」の項目・断られた項目を書く。日次報告を使うなら `daily_report` の `enabled`・`time`・`priorities`（質問2の優先順位を1行に）・`departments`（参加させる部門。`agent` は `agents/` のフォルダ名と一字一句同じにする）も埋める。使わないなら `enabled` を `false`、`departments` を空の配列にする。会話ログからの学習を希望されたら `learning.enabled` を `true` にする。**`setup_completed` はPhase 4の検証が終わるまで空のままにする。**
7. **フック設定** — `.claude/settings.template.json` の `{{HUB_PATH}}`(このリポジトリの絶対パス)と `{{PYTHON_CMD}}`(`python3` が使えるか確認し、なければ `python`。Windowsは通常 `python`)を置換して `.claude/settings.json` を生成（ダッシュボード有効時のみ。無効なら作らない）。
   - **【Windows必須】`{{HUB_PATH}}` は必ずスラッシュ区切りで書く**（例：`C:/Users/taro/agent-hub`）。バックスラッシュ（`C:\Users\...`）をそのまま入れるとJSONのエスケープ文字と衝突して**設定ファイル全体が壊れ、フックが一切動かなくなる**。PythonはWindowsでもスラッシュ区切りのパスをそのまま扱えるので問題ない。生成後は必ずJSONとしてパースできるか検証すること（`{{PYTHON_CMD}} -c "import json;json.load(open('.claude/settings.json'))"` が黙って成功すればOK）。

## Phase 3：外部連携（希望されたものだけ）

`integrations/` の該当ガイドを読み、**導入者と一緒に**設定する。ターミナル操作はClaudeが実行し、ブラウザでの認証・アプリのインストールだけ導入者にお願いする。

- Obsidian → `integrations/obsidian.md`（Vaultパスを特定して `hub.config.json` に記録）
- Googleカレンダー → `integrations/google-calendar.md`
- Notion → `integrations/notion.md`
- Claude in Chrome → `integrations/claude-in-chrome.md`
- ダッシュボード → `dashboard/README.md`（`python3 dashboard/install_dashboard.py`）
- 日次報告 → `framework/03_日次報告.md`（`python3 scripts/install_daily_report.py` で毎朝の自動起動を登録する。Phase 4 の検証が通ってから登録する）
- LINE通知 → `integrations/line-notify.md`（トークンは導入者が自分でターミナルに入力する。司令塔は受け取らない）

連携は**後回しにしてもよい**。「あとで `integrations/◯◯.md` の設定をやりたい」と言えばいつでも設定できる、と伝える。

## Phase 4：検証（5分）

1. **テスト委任**：作った部門の1つに簡単な作業（「今の記録の状態を確認して」等）をAgentツールで委任し、報告が返ることを確認する。
2. **検収の確認**：1の報告の末尾に根拠ファイル欄があり、そこに書かれたパスが実在することを確かめる。無ければ、そのエージェントの指示書と共通プロトコルを見直す。
3. **日次報告の試運転**（日次報告を使う場合）：`{{PYTHON_CMD}} scripts/claude_manager.py run --force` を一度走らせ、`{{PYTHON_CMD}} scripts/claude_manager.py show` で結果が読めることを確かめる。データが少なければ「報告はなし」が正常。「届かず」が出たら理由を読んで直す（`framework/03_日次報告.md` の「うまく届かないとき」）。通ったら `{{PYTHON_CMD}} scripts/install_daily_report.py` で自動起動を登録する。
4. 問題なければ `hub.config.json` の `setup_completed` に今日の日付を記入する。
5. 最後に使い方の要点を伝える：
   - 普段は話しかけるだけ（司令塔が適切な部門に振り分ける）
   - 日次報告を有効にしたなら、毎朝ダッシュボードに各部門の報告が並ぶ（「今日の報告は？」でも読める）
   - 部門の追加・変更は「◯◯の部門を作りたい」と言えばよい
   - 出てきたものが違うと思ったら、その場で直してよい。直されたことは覚えて、次から守る
   - 使っていて「これ毎回面倒だな」と思ったら、そのまま言ってほしい。手を動かさずに済む仕組みを作れることがある（ここでは道具の種類を並べない。場面が出たときに `framework/07` で提案する）
   - 情報はあとからいつでも足せる。今日飛ばした項目も、思い出したときに話してくれれば預かる（急がなくてよい）

## セットアップ後の変更・再セットアップ

- 部門の増減：`framework/05` パターン10の手順で司令塔がいつでも実施できる。
- プロファイルの更新：本人の状況が変わったら `shared/profile/ユーザープロファイル.md` の更新を提案する。
- 情報の追加：文章例・ヘルス情報・支払いのまとまり・持っている物・収入と固定費・資産は、使い始めてからきっかけが来たときに勧める（`setup/情報の預かり方.md` の「あとから勧めるもの」）。セットアップ中には求めない。
- 完全にやり直したいとき：`hub.config.json` を削除して起動し直せばウィザードが再実行される（生成済みの部門・データは消えないので、上書き可否を都度確認しながら進める）。
