# 連携ガイド：Googleカレンダー（gcalcli）

## 何ができるようになるか

- エージェントがあなたのGoogleカレンダーを読み取り、タスクリストと突き合わせて「締切イベントの拾い漏れ」を検知できる。
- カレンダー＝予定の一次ソース（本人がスマホ/PCで管理）、タスクリスト＝行動タスク、という役割分担が組める。

## 前提

- ターミナル操作はClaudeが代行する。導入者がやるのは**ブラウザでのGoogle認証**と、Google Cloudでの初期設定（初回のみ・10〜15分）。
- `gcalcli` は Python 製のツールで **Mac / Windows / Linux 共通の手順**でインストールできる（`pip` を使う。OS依存のパッケージマネージャーは不要）。

## 手順

1. **インストール**（Claudeが実行。どのOSでも同じコマンド）：
   ```bash
   pip install gcalcli
   ```
   ※ `pip` が見つからない場合は `pip3` を試す。Windowsで両方失敗する場合は、先にPython公式サイトからPythonをインストールする（インストール時に「Add python.exe to PATH」にチェック）。
2. **Google Cloud で OAuth クライアントを作る**（導入者がブラウザで実施。Claudeが画面ごとに案内する）：
   1. https://console.cloud.google.com/ にGoogleアカウントでログイン
   2. 新しいプロジェクトを作成（名前は `gcalcli` など何でもよい）
   3. 「APIとサービス > ライブラリ」で **Google Calendar API** を有効化
   4. 「APIとサービス > OAuth同意画面」でアプリを構成（ユーザータイプ：外部、テストユーザーに自分のGmailを追加）
   5. 「認証情報 > 認証情報を作成 > OAuthクライアントID」で種類「**デスクトップアプリ**」を作成し、**クライアントID**と**クライアントシークレット**を控える
3. **初回認証**（Claudeがコマンドを実行し、ブラウザが開いたら導入者が許可する）：
   ```bash
   gcalcli --client-id （クライアントID） --client-secret （シークレット） list
   ```
   カレンダー一覧が表示されれば成功。
4. **`hub.config.json`** の `integrations.google_calendar` を `true` にし、`google_calendar_id` にメインカレンダーのID（通常は自分のGmailアドレス）を記録する。
5. タスク管理系エージェントのCLAUDE.mdに読み取りコマンド例を記載する：
   ```bash
   # 今後2週間の予定
   gcalcli --calendar "（カレンダーID）" agenda （今日） （2週間後） --nocolor
   ```

## 運用ルール（重要）

- **読み取り中心。** 予定の追加（`gcalcli add`）は本人が明示的に「カレンダーに入れて」と言ったときのみ。勝手に追加・変更・削除しない。
- カレンダーの予定を全部タスクリストに写さない。拾うのは「やらないと締切に間に合わない行動」（納品・提出・支払い等）だけ。人と会う予定・祝日などは拾わない。
- **認証が切れたら**：エージェントは自分で再認証を試みず「再認証が必要」と報告する。再認証は上記手順3を再実行。

## つまずきやすい点

- OAuth同意画面で「テストユーザー」に自分を追加し忘れると認証がブロックされる。
- 認証トークンは（Macなら `~/.config/gcalcli/`、Windowsなら `%APPDATA%\gcalcli\` 相当）に保存される。マシンを変えたら再認証が必要。
- **Windows**：`gcalcli` コマンドが「認識されません」と出る場合、pipでインストールした実行ファイルの場所がPATHに通っていない可能性がある。その場合はPythonの再インストール時に「Add to PATH」を有効にするか、`python -m gcalcli` の形で呼び出す。
