# framework/07 — 道具を作ってつなぐ（面倒を、自分専用の仕組みに変える）

司令塔がこのファイルを読むのは、オーナーの話に「面倒」「毎回」「いちいち」「手で」「また同じ」「忘れる」が出たとき、同じ頼みごとが2回目だと気づいたとき、「自動でできない？」「もっと楽にしたい」と言われたとき、または道具を作る・直す・止めるとき。日常のモードAでは読まない。

このハブは、記録を預かるだけの仕組みではない。**オーナーの手を動かさずに記録が入り、頼まれる前に揃っている**状態まで育てられる。そのために、Claude Code でオーナー専用の小さな道具を作り、ハブにつなぐ。オーナーがプログラムを書けなくてよい。作るのは Claude で、オーナーは「何が面倒か」を話すだけでよい。

---

## 提案の決まり

1. **頼まれたことを先に済ませる。** 提案はそのあと、返事の最後に添える。
2. **1回に1案だけ。** 選択肢を並べない。いちばん手間が減る案を1つ選ぶ。
3. **場面が実際に出てから提案する。** 同じ面倒が2回出た、または本人が「面倒」と言ったとき。セットアップ直後に道具の話を並べない。
4. **ふつうの言葉で言う。** 「Chrome拡張を作りましょう」ではなく、「売上のページを開いたら、ボタン1つで記録に入るようにできます」と、何が楽になるかで言う。仕組みの名前は聞かれたら答える。
5. **かかるものを正直に添える。** 作るのにかかる時間の目安、オーナーにやってもらうこと（ログイン・インストール・許可）、毎日の使用量が増えるかどうか。
6. **作るかどうかはオーナーが決める。** 断られたら、「わかりました、今のままで続けます」と一言で受け止めてから、`my-hub/司令塔設定.md` の「道具」表に「見送り」と書き、同じ案を繰り返さない。事情が変わったとき（回数が大きく増えた等）だけ、もう一度だけ言う。
7. **一回限りの作業に道具を作らない。** 月に1回もやらないことは、手でやるほうが安い（`framework/01` 原則1）。
8. **先に手持ちで済むか確かめる。** `shared/profile/利用サービス一覧.md` を読み、今使っているサービスの機能（自動の書き出し・通知・連携）で足りるなら、作らずにそれを案内する。

## 道具の型（困りごと → 効く型）

| 困りごとの形 | 効く型 | 何ができるか |
|---|---|---|
| 毎日・毎週、同じ数字を見に行って伝えている | **定期実行** | 決まった時刻に取りに行き、記録に書いておく |
| メールで届く通知（請求・入金・予約）を手で写している | **定期実行（メール読み取り）** | 届いたメールから金額や日付を拾い、記録に入れる |
| あるサイトを開くたびに、同じ操作・同じ保存をしている | **ブラウザ拡張** | ページを開いたら自動で保存・振り分け、またはボタン1つでハブへ渡す |
| サイトの画面に、欲しい数字や計算が出ていない | **ブラウザ拡張** | 画面に計算結果や印を足して表示する |
| パソコンで毎日する決まった動作がある | **小さなアプリ** | ショートカット1つで済むようにする。タイマーで時間を自動で記録する |
| 外出先・寝る前など、パソコンの前にいないときに記録したい | **スマホからの受信箱** | メモアプリやショートカットから一言送ると、あとで部門が取り込む（`framework/05` パターン3） |
| スマホやウェアラブルにたまる記録（睡眠・歩数など）を使いたい | **スマホからの受信箱（自動）** | 毎朝スマホが記録を書き出し、ハブが取り込む |
| 結果を見に行くのを忘れる | **通知** | 毎朝の報告をスマホに届ける（`integrations/line-notify.md`） |
| 「◯◯と言ったら、いつもこの処理」が決まっている | **合言葉（フック）** | 決まった一言で、決まった記録や処理が始まる |

### 例（どれも実際に動いている使い方を一般化したもの）

- **サブスクやカードの利用通知のメール → 家計の記録へ。** 毎朝メールを読み、金額・店名・日付を拾って記録に足す。オーナーは何も入力しない。
- **SNSや動画の再生数・登録者数 → 実績の表へ。** 毎朝、公式の仕組み（API）で数字を取り、1冊の表にためる。「今月どうだった？」に、聞き直しなしで答えられる。
- **カレンダーのシフト → 来月の入金見込みへ。** 予定から勤務時間を数え、時給をかけて見込みを出しておく。
- **持ち物の中古相場 → 価格の履歴へ。** 毎朝相場を調べてためる。「今売ったらいくら？」にすぐ答えられる。
- **学校や職場のサイトで開いた資料 → 科目・案件ごとのフォルダへ。** ブラウザ拡張が、開いたPDFを自動で保存して振り分ける。
- **参考にしたいサイト → 台帳へ。** 見ているページでボタンを押すと、URLとメモが台帳に入る。次に何か作るとき、部門がそれを読んでから作る。
- **証券や家計のサイトの画面 → 欲しい計算を足して表示。** サイトが出してくれない割合や合計を、画面の上に足す。
- **Webのフォームの設問 → 担当の部門へ。** フォームを開くとボタンが出て、設問を担当の部門に渡して下書きを始める。回答欄には触らない。
- **練習や勉強の時間 → 記録へ。** メニューバーのタイマーを押すだけで、時間が記録に入る。
- **画面の一部を撮る → Claudeに貼る。** ショートカット1つで、撮って貼るまでを済ませる。

## ハブへのつなぎ方（ここを守らないと、道具が増えるほど壊れる）

1. **書き込む先は、担当の部門のデータ置き場**（`shared/部門名/`）。道具ごとに勝手な置き場所を作らない。
2. **1ファイル1書き込み担当を守る。** 道具が書くファイルは、`my-hub/司令塔設定.md` の所有権表に「書き込み担当：道具の名前」と書く。同じファイルに部門のエージェントも書くなら、道具は別のファイル（受信箱）に書き、エージェントが取り込む形にする。
3. **道具が書くファイルを正本にする。** 手で写した控えを別に持たない（`framework/05` パターン11）。
4. **担当の部門の指示書に書く。** `agents/XX/CLAUDE.md` のデータソース表に、そのファイルと「自動で入る。聞き直さない」の一言を足す。
5. **止まったら気づけるようにする。** その部門の日次報告の観点に「最後に取り込まれた日」を足す。
6. **道具の一覧を持つ。** `my-hub/司令塔設定.md` の「道具」表に、名前・何をするか・置き場所・動く時刻・書き込む先・止め方を書く。
7. **置き場所。** 定期実行の小さなスクリプトは `scripts/` に、ブラウザ拡張やアプリのように大きくなるものは、ハブの外に専用のフォルダ（例：ホームフォルダの下）を作る。どちらも「道具」表に場所を書く。

## 作るときの決まり

- **小さく作る。** 最初は1つのことだけをする。うまく動いてから足す。
- **オーナーの実物で1回試す。** 本物のメール1通・本物のページ1枚で動かし、入った記録をオーナーに見せてから自動にする。
- **自動にする前に、止め方を伝える。** 登録の解除方法を「道具」表に書き、口頭でも一言伝える。
- **Mac でも Windows でも動く形で書く。** スクリプトは Python で書き、定期実行の登録は `scripts/install_daily_report.py`（Mac＝launchd／Windows＝タスクスケジューラ）を手本にする。
- **求める許可は最小にする。** ブラウザ拡張は、必要なサイトだけ・必要な権限だけ。あとから権限を足さない。足す必要が出たら、理由を伝えてオーナーに決めてもらう。
- **鍵・トークンを預からない。** 外のサービスの鍵が要るときは、オーナーが自分でターミナルに入力する形にする（`scripts/phone_notify.py setup` が手本）。鍵は git に載らない場所に置く。
- **お金が動く操作は自動にしない。** 購入・送金・売買・解約は、道具にも司令塔にもやらせない。読むだけにする。
- **相手のサービスの決まりを守る。** 公式の取り出し口（書き出し・API・通知メール）があればそれを使う。自動の読み取りを禁じているサービスには使わない。
- **制作は重いモデルで。** 道具そのものを作る作業は、出来がそのまま毎日の正しさになる（`framework/04`）。

## 作ったあと

- 1週間、日次報告で取り込みが続いているかを見る。
- オーナーが道具の出した結果を手で直したら、その差を道具の決まりに反映する（`framework/05` パターン12）。
- 使われなくなった道具は、登録を解除して「道具」表を「停止」にする。コードは消さない。
