# framework/06 — 会話ログからの学習

司令塔がこのファイルを読むのは、オーナーが「覚えたこと」「学習」「それは覚えなくていい」「取り消して」と言ったとき、または仕組みを直すとき。日常のモードAでは読まない。

目的は、オーナーが同じ直しを二度言わずに済むこと。

---

## 何をする仕組みか

毎朝、日次報告を集める前に、前回読んだところから先のオーナーとの会話ログを読み返し、次から言わせずに済むことをメモリに足す。オーナーの確認は取らず、結果を日次報告の「学習」の段に事実だけ載せる。

- 動かしているのは `scripts/session_learner.py`。`hub.config.json` の `learning.enabled` が `true` のとき、`scripts/claude_manager.py` が毎朝の報告の前に呼ぶ。**日次報告の自動起動を使っていることが前提**。
- 読むのは、このフォルダで交わした会話のログ（Claude Code が `~/.claude/projects/` の下に残すもの）。
- 拾うのは4種類：訂正／恒久の指示（「今後は」「毎回」）／答えた確認／手で頼んだ定型作業。
- **別々の会話で2回見たものだけ**メモリに書く。一回限りの手直しや冗談を決まりにしないため。
- メモリを書いたあとに始まった会話で、また直された訂正は、そのメモリを書き直す（当てはまる場面とやることを具体的にする。もとの内容は削らない）。
- 手で頼んだ定型作業は、3つの会話で見たら「自動化の候補」として報告に出すだけ。作るかどうかはオーナーが決める。
- 書く先はメモリ（`feedback-*.md` と目次の `MEMORY.md`）だけ。`agents/XX/CLAUDE.md`・共通プロトコル・設定ファイルは自動では書き換えない。
- 台帳は `dashboard/learner/`（`candidates.json`＝様子見も含めた全候補、`state.json`＝どこまで読んだか、日付のJSON＝その日に覚えたこと）。オーナーの発言の抜き書きが入るのでgitには載せない。

会話を読み返す分、毎朝の使用量が増える（会話の多い日ほど増える）。

## 司令塔が頼まれたとき

- 「何を覚えた？」→ `python3 scripts/session_learner.py show` を読んでそのまま伝える。
- 「それは違う」「12番は覚えなくていい」→ `python3 scripts/session_learner.py undo 12`。覚えたものはメモリごと消え、二度と覚えない。書き直したものは書き直す前に戻り、以後そのメモリは書き直さない。
- 様子見の中身を見たい → `python3 scripts/session_learner.py list`
- 読み直したい → `python3 scripts/session_learner.py run --days 7`（`--dry` を付けると何も書かずに下書きだけ出す）
- 始める・止める → `hub.config.json` の `learning.enabled` を直す。

Windowsでは `python3` の代わりに `python` を使うことがある（`hub.config.json` の `environment.python_cmd`）。

## 覚えたメモリを、サブエージェントに効かせる

メモリを読むのは司令塔。サブエージェントの作業に効く決まりは、メモリの How to apply に「委任文にも書く」と入る。司令塔は委任の前に、その部門に当たるメモリの決まりを委任文の補足に書く。同じ決まりが何度も書き直されるようなら、メモリではなく `agents/XX/CLAUDE.md` か共通プロトコルに移す（これは司令塔が手で行う）。

## 直すとき

- 拾う基準・書き方 → `scripts/session_learner.py` の `SPOT_PROMPT`・`MATCH_PROMPT`・`WRITE_PROMPT`
- 何回で覚えるか → 同じファイルの `NEED`
- 表示 → `dashboard/index.html` の `renderManager()`（`learned` の段）

## うまく動かないとき

- 「会話ログの置き場が見つからない」→ このフォルダで `claude` を一度も使っていないか、フォルダを移動した。移動したあとは、新しい場所で会話した分から読まれる。
- 何も覚えない → 正常。2回目が出るまでは様子見に入る。`list` で確かめられる。
