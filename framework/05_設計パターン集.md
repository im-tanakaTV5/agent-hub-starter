# framework/05 — 設計パターン集（部門設計・運用の定石）

部門を作る・育てる・畳むときの定石集。セットアップ時と、運用中に部門を増減するときに参照する。

---

## パターン1：分割エージェント（`b`/`c` 付き）

1つの部門の中に性質の違う仕事が同居してきたら、エージェントを分割する（例：`02_家計` と `02b_節税`）。

- **分割の基準**：①データへの権限が違う（記帳は読み書き、税アドバイスは読み取りのみ）、②必要なモデルティアが違う、③片方だけオンデマンド専用、のどれかに該当したら分割を検討。
- 分割してもレポート上は**1部門1カード**に統合する（`framework/02` 処理0）。
- 番号は親と同じにして `b`/`c` を付ける（部門の同一性が一目で分かる）。

## パターン2：部門長エージェント

配下エージェント間に**依存関係（Aの出力を受けてBが再計算する逐次パイプライン）**がある部門だけ、まとめ役の部門長を置く。

- 例：`10_資産部門長` が「10b（マクロ経済予測）→ 10（保有資産に当てて再計算）」の順で配下を起動し、往復統合した部門レポートを返す。
- 司令塔はこの部門については部門長にだけ委任する。配下を直接起動しない。
- **配下が独立・並列なら部門長は置かない**（司令塔が直接統合すれば足りる。階層は増やすだけコスト）。
- 依存関係が消えたら部門長は廃止する（例：引越しが完了して「探す→チェック」のパイプラインが不要になったら、常設の生活部門に再編して部門長を外す）。

## パターン3：quick-log（受信箱）パターン

オーナーがスマホから走り書きする「受信箱」ファイルと、エージェントが管理する「正式な記録ファイル」を分ける。

- 例：Obsidianの `quick-log/練習メモ.md` にオーナーが走り書き → 担当エージェントが読み取り、正式な記録（CSV/xlsx）に整形して取り込み、**取り込み済み行に ✅ を付ける**。
- 受信箱はオーナーの書き方を勝手に整形しない。エージェントは「取り込みマーク」だけ付ける。

## パターン4：課題台帳（記憶の輪）パターン

週次レポートは数日で捨てるが、**浮き彫りになった課題と答え合わせ結果は台帳（`これまでの活動.md`）に蒸留して永続させる**。

- 台帳には課題ごとに：一貫ID・部門・担当エージェント番号・発生日・状態（✅/🔄/❌/⤴）。
- 繰越時は**元の発生日を保持**する（何週オープンか分かる）。3週以上で「慢性課題」として総評で名指し。
- オーナーがスマホから手でチェックを入れてよい。エージェントは次週それも解決判定の材料にする。
- 詳細フローは `framework/03` の手順6。

## パターン5：データ所有権（1ファイル1書き込み担当）

- どのファイルも**書き込めるエージェントは1体だけ**。他は読み取り専用。司令塔も読み取りのみ。
- オーナー所有のファイル（目標リスト等）はエージェントは進捗確認に徹し、書き込みはオーナーが明示したときだけ。
- 対応表は `my-hub/司令塔設定.md` に持ち、部門の増減時に必ず更新する。
- **数値の書式**：xlsxに書き込むエージェントは、金額・時間などのセルに表示書式を適用して保存する（金額は `#,##0` など）。書式なしの書き込み禁止。
- **再計算エンジンの罠**：エージェントがxlsxを編集しても数式は再計算されない。合計行などは**数式ではなく固定値で書き、担当エージェントが更新時に手動追随**させる方が安全。

## パターン6：部門間トリガー

「あるデータの変化が別部門の作業を発生させる」関係は、司令塔設定に**トリガー規則**として明文化する。

- 例：「家計簿に ¥100,000 以上の事業経費が記録されたら、節税エージェントに固定資産登録を確認させる」。
- トリガーの検知と発火は司令塔の仕事（統合時・委任時にチェック）。実作業は担当エージェントに委任する。

## パターン7：提出・納品後の後片付け

オーナーが「提出した」「終わった」「もういらない」と完了を示したら、**担当エージェントに委任して**後片付けを自動実行させる。司令塔が直接ファイルを消さない・動かさない。

- 手順の型：①削除対象のパス一覧を提示 → ②成果物のみ削除 → ③参照資料はアーカイブフォルダへ移動して保管 → ④迷うものは消さず確認。
- 「整理して」「片付けて」等の整頓系依頼もトリガーとして拾う。ただし完了が明言されていなければ、削除可否の確認を挟ませる。
- **他部門の共有データ・オーナー自作でないファイルの削除は例外なく禁止。**

## パターン8：既読管理付きリサーチ

ニュース・情報収集系の部門は、**リサーチログファイル（例：`shared/resources/◯◯-news.md`）に追記して既読管理**する。同じ話題を毎週報告しない。ログに追記できるのは担当エージェントのみ。

## パターン9：文体学習ファイル

文章生成系の部門（メール・レポート等）には、**オーナー本人の文章サンプル集**（`自分の文章例.txt` 等）を持たせ、生成時に必ず文体を寄せさせる。サンプルが増えるほど精度が上がるので、良い実物ができたらオーナーがファイルに追加する運用を促す。

## パターン10：部門の増設・廃止

- **増設**：`templates/agent.template.md` から `agents/NN_名前/CLAUDE.md` を作り、`shared/` にデータ置き場を作り、`my-hub/司令塔設定.md` の部門表・振り分け表・所有権表に行を追加する。この3点セットで完了。
- **廃止**：部門表から外し、データは `shared/` に残す（消さない）。エージェントフォルダは `agents/_retired/` に移す。
- 変更したら `python3 scripts/sync_agents_md.py（Windowsは python の場合あり）` を実行（Antigravity互換を使っている場合。Claude Codeではフックが自動実行）。
